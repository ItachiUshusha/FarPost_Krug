# Круг · Material Design

Создавай цельный Material Design 3 интерфейс «Круга»: спокойный, тактильный, удобный на телефоне и выразительный в демонстрации обмена. Красота должна помогать понять, что человек отдаёт, получает и делает дальше.

## Контекст и границы

Работай с запрошенными экранами и текущей версией продукта. Прочитай `AGENTS.md`; при работе с Next.js используй установленную документацию `node_modules/next/dist/docs/`. В репозитории «Круга» спецификация находится в `docs/krug-codex-prompt.md`.

Сохраняй бизнес-состояния, права участников, данные, маршруты и реальные обработчики. Запрос на дизайн не означает реализацию всего бэкенда, публикацию или замену работающих данных фикстурами. Если запрошен только обзор, дай конкретные находки без изменения файлов.

## Материалы по задаче

- Для нового экрана или темы прочитай [references/design-system.md](references/design-system.md); исходные токены — [assets/krug-material-tokens.json](assets/krug-material-tokens.json).
- При подключении или изменении React/MUI-кода прочитай [references/react-integration.md](references/react-integration.md). Проверь актуальные версии, совместимость и официальную интеграцию; не копируй устаревший импорт адаптера.
- Для мобильного интерфейса используй Framework7 React и прочитай [references/framework7-mobile.md](references/framework7-mobile.md). Это явный выбор пользователя; Material UI предназначен для десктопной оболочки.
- Для визуальной проверки и завершения UI-задачи используй [references/visual-review.md](references/visual-review.md).

Не загружай остальные справочники, если они не нужны текущему действию. Пути справочников и ассетов относятся к этой папке навыка; пути приложения — к корню текущего проекта.

## Дизайнерские решения

До вёрстки определи основное действие, иерархию содержимого и один узнаваемый мотив. Для «Круга» это передача по окружности: мягкие контейнеры, округлые action-кнопки, связанные участники. Применяй мотив избирательно, чтобы длинные русские тексты, таблицы и формы оставались читаемыми.

Строй интерфейс из семантических ролей `primary`, `primaryContainer`, `surfaceContainer`, `onSurface`, `outline`, `error`, а не из разрозненных цветов. Переиспользуй тему, типографику и несколько согласованных компонентов. Точные значения в ассете — стартовая палитра проекта, не универсальный стандарт Material.

Мобильную оболочку реализуй на Framework7 React с Material-темой `theme: 'md'`, десктопную — на тематизированных Material UI компонентах. Общими остаются дизайн-токены, DTO, API, сессии, состояние форм и бизнес-правила. Разделяй представления без двух независимых реализаций обмена. Стандартная тема библиотеки сама по себе не задаёт готовую визуальную систему «Круга».

Один главный CTA на смысловой блок. В карточке заявки сразу различимы «Отдаёт» и «Хочет». В карточке круга — личный результат и число участников. В подробностях круга схема сопровождается доступным текстом передач и реальными статусами ответов.

Используй конкретные интерфейсные состояния: default, hover, focus-visible, pressed, disabled, loading, error, success. Действие подтверждается ответом API. Отказ показывает следующий доступный шаг. Цвет участника не заменяет подпись, номер или статус.

Проверь компактную и широкую композицию, длинные названия, увеличенный текст, клавиатуру и отсутствие горизонтальной прокрутки страницы. Выразительную анимацию оставляй для причинных изменений: выбор, появление результата, обновление круга. Соблюдай `prefers-reduced-motion`.

## Проверка и результат

Для палитры ассета выполни из корня проекта:

```bash
node .agents/skills/krug-material-design/scripts/check-contrast.mjs
```

Скрипт принимает также путь к JSON в том же формате. При реализации перенеси рабочие токены в обычный исходный модуль приложения: runtime не должен импортировать файлы из папки навыка.

Проверь изменённый пользовательский сценарий в доступном браузере, а для React-кода — подходящие `lint`, `typecheck` и сборку. Не объявляй визуальную проверку выполненной только по успешной сборке. Если браузер недоступен, укажи ограничение.

В завершении коротко сообщи изменённые экраны, принятые визуальные решения, фактически проведённые проверки и оставшиеся проблемы. Если нужны замечания по дизайну, привязывай их к конкретному экрану и действию пользователя.
