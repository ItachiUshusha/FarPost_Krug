# React, Framework7, Material UI и существующий Next.js

## Выбор библиотеки в пределах задачи

В исходном проекте используется обычный CSS и компоненты Data Studio. Для нового мобильного интерфейса пользователь выбрал Framework7 React с Material-темой; для десктопного — Material UI. Мобильные особенности описаны в [framework7-mobile.md](framework7-mobile.md); дальнейшие замечания о MUI относятся к десктопной оболочке.

Framework7 и MUI используются в отдельных представлениях с общими API, сессией, моделями, состоянием формы и токенами. Не смешивай элементы двух библиотек на одном экране и не добавляй третью полноценную UI-библиотеку. Небольшого SVG для 2–4 участников достаточно.

## Версии и streaming

Прочитай `AGENTS.md`, `package.json` и актуальные локальные руководства Next.js. Перед установкой проверь `peerDependencies` выбранного MUI и наличие нужного App Router adapter в exports пакета. Не ставь canary/next-релиз вместо стабильного ради примера из документации.

Для стандартной MUI/Emotion интеграции нужны совместимые `@mui/material`, `@emotion/react`, `@emotion/styled`; поддержку streaming и cache сверяй с `@mui/material-nextjs` и `@emotion/cache`. Иконки подключай только если они действительно используются; не ставь весь набор ради одной стрелки.

Используй текущую [официальную интеграцию MUI с Next.js](https://mui.com/material-ui/integrations/nextjs/). Выбери реально существующий экспорт `AppRouterCacheProvider` для установленного адаптера; номер Next.js сам по себе не гарантирует наличие пути `v16-appRouter`.

Корневой layout может оставаться серверным. Theme/provider и интерактивные компоненты получают корректную client-boundary. Учти серверный сбор стилей, их порядок и стабильный первый рендер. Если Framework7 требует браузерного окружения, ограничь загрузку без SSR только его клиентской оболочкой с содержательным fallback; не отключай SSR всему приложению ради обхода ошибок интеграции.

Если используешь глобальный `CssBaseline`, проверь его влияние на `/studio`; при необходимости ограничь reset продуктовой частью или согласуй существующие глобальные стили. Изолируй старые селекторы `button`, `table`, `.dialog` и `.button` от новой темы. При смешивании Emotion и CSS Modules порядок/слои должны быть явными и проверенными.

`next/link` и проп `component` должны проходить правильную границу клиента. При ошибке передачи функции не понижай Next.js — используй документированный клиентский адаптер ссылки. У `useSearchParams` учитывай требования установленного Next.js к `Suspense`; fallback сохраняет геометрию фильтра/toolbar.

## Тема

Общие токены, например `src/theme/krug-tokens.ts`, становятся источником истины; адаптеры экспортируют их в MUI theme и CSS-переменные Framework7. Копирование стартовых значений из ассета навыка — однократная операция. Пакет навыка не нужен приложению во время выполнения.

Минимально согласуй:

- семантическую палитру и `primaryContainer`/surface-роли;
- типографику и локальный кириллический шрифт;
- shape и spacing;
- Buttons, Chips, TextFields, Cards, Dialogs, Tabs и состояния фокуса;
- контролируемую анимацию и reduced motion.

Сделай тональные варианты через тему/общие обёртки, если текущий MUI не имеет нужного варианта. Не разбрасывай десятки индивидуальных `sx`-значений ради одного и того же компонента. Локальный `sx` остаётся удобным для конкретной раскладки.

Не меняй глобально размер `1rem` ради уменьшения всего интерфейса. Установи понятную иерархию размеров; поля на телефоне остаются удобными для ввода. Динамические API-состояния передавай из имеющегося домена, не дублируй их в отдельной «визуальной» модели.

Тёмный режим, пользовательский theme editor и Storybook создавай только по соответствующему запросу. Для MVP хватит небольшой внутренней витрины компонентов, если она нужна для реального повторного использования.

## Проверка интеграции

Проверь обычную загрузку, прямой переход на вложенный маршрут, обновление страницы, навигацию, диалог и изменение фильтра. В консоли нет ошибок гидратации, функции не протаскиваются через серверную границу, стиль не мигает при первом открытии.

Выполни подходящие `npm run typecheck`, `npm run lint`, `npm run build`; для текущего сценария — браузерную проверку. Существующий Data Studio и его тесты должны оставаться рабочими. Если меняются только инструкции навыка, вместо сборки приложения валидируй пакет и его утилиты.
