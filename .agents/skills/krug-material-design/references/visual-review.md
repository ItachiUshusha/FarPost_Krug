# Проверка интерфейса «Круга»

Используй при запрошенном дизайн-ревью или перед завершением реализации экрана. Оценивай реальные состояния страницы и содержимое, а не только идеальную пустую карточку.

## Экран и действие

Проверь исходный экран и один завершённый путь пользователя. В каталоге он понимает различие «Отдаёт»/«Хочет»; в форме видит ошибку и сохраняет введённое; в круге понимает личный результат и свой следующий шаг.

Если запрошен только обзор, перечисли проблемы по влиянию: блокирующая действие → существенная неоднозначность → заметный визуальный дефект → косметика. Для каждой дай экран, состояние, наблюдение и конкретное исправление. Не подменяй находки абстрактным пожеланием «сделать современнее».

## Композиция и тема

- Главный заголовок, результат и действие различаются по важности; дополнительная статистика их не подавляет.
- Поверхности, цветовые роли, радиусы и типографика повторяются последовательно.
- Выбранный chip, focus, loading и disabled не выглядят одинаково.
- Окно, меню и tooltip не обрезаются и не скрывают основной CTA.
- Длинные русские названия и четыре участника не ломают композицию.
- Пустое состояние, нулевой результат и отказ отличаются по смыслу и следующему действию.

## Доступность

Проверь keyboard-only путь: nav → фильтр/форма → действие → диалог → возврат фокуса. Есть видимый focus ring, реальные label, доступные имена и понятные сообщения об ошибках. При открытом модальном окне фон не перехватывает клавиатуру.

Проверь фактический контраст текста/контролов, а не только базовый JSON. Названия и статусы остаются понятны без различения цветов. При увеличении текста до 200% не теряются обязательные действия. Для reduced motion переходы сохраняют смысл без длительной анимации.

## Адаптивность

Базовые проверки: 390×844 и 1440×1000. Дополнительно проверь 320 px и среднюю ширину около 768 px, если меняется раскладка или есть плотная форма/схема.

Страница не имеет горизонтального скролла; намеренно прокручиваемая таблица ограничена собственным контейнером. На телефоне нижняя навигация/CTA учитывает safe area; экранная клавиатура не делает сохранение недоступным. Проверка `scrollWidth` полезна, но не заменяет просмотр длинного содержимого.

Для Framework7 проверь нижнюю tabbar, открытие и закрытие sheet/popup, аппаратный или браузерный Back, прямую ссылку и обновление страницы. Повторная инициализация в React StrictMode не создаёт вторую оболочку, события или запросы. После смены ширины черновик и сессия остаются прежними; глобальный CSS Framework7 не ломает MUI и `/studio`. Не считай iOS swipe-back обязательным поведением Material-темы.

## Круг и состояния API

Сверь схему с серверным порядком передачи, включая последнее замыкающее ребро. Получатель вещи не меняется ради более симметричной картинки. Текстовый список согласован со SVG.

Проверь pending, частичные подтверждения, agreed, declined и конфликт изменённой заявки, если они входят в задачу. Кнопки доступны только соответствующему участнику. Повторный клик и ошибка сети не создают видимость принятого решения.

## Доказательства

При доступном браузере сохрани несколько нужных скриншотов в игнорируемую `.local/qa/`, проверь console errors и один основной сценарий. Для набора компонентов достаточно репрезентативных состояний; не вводи трудоёмкую snapshot-инфраструктуру без необходимости.

Если браузер недоступен, обозначь это и выполни доступные статические/функциональные проверки. Не утверждай, что мобильная композиция или контраст были визуально проверены.
