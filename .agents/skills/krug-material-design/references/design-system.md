# Визуальная система «Круга»

## Характер

«Круг» — городской обмен вещами. Интерфейс должен ощущаться человеческим и спокойным: натуральный зелёный основной акцент, тёплые светлые поверхности, уверенная типографика и понятные связи между людьми. Выразительность M3 достигается контрастом размеров, форм и состояний в ключевых местах.

Исходная тема — светлая. Тёмная тема нужна только при соответствующем запросе; это самостоятельная палитра с проверкой контраста, а не инверсия цветов. Не увеличивай объём задачи ради переключателя темы.

## Цветовые роли

Канонические стартовые значения находятся в `../assets/krug-material-tokens.json`. В приложении используй один источник токенов, экспортированный в CSS-переменные Framework7 для мобильной оболочки и MUI theme для десктопной.

| Роль | Применение |
| --- | --- |
| primary / onPrimary | Основное действие: добавить заявку, найти круг, подтвердить интерес. |
| primaryContainer / onPrimaryContainer | Выбранный вариант, мой участник, полезный итог обмена. |
| secondaryContainer / onSecondaryContainer | Дополнительные управляющие элементы, спокойные фильтры. |
| tertiaryContainer / onTertiaryContainer | Вторичный акцент: многосторонний вариант, отдельный участник, пояснение. |
| surface / onSurface | Основной фон и читаемый текст. |
| surfaceContainerLow / Container / High | Группировка карточек, панелей, формы и диалога. |
| onSurfaceVariant | Подписи, пояснения и метаданные, которые остаются читаемыми. |
| outline | Граница активного поля/контрола, когда она необходима для распознавания. |
| outlineVariant | Декоративные разделители и несущественные границы. |
| error / errorContainer | Ошибка поля, отказ, конфликт с понятным объяснением. |

Сочетай фон роли с её `on...` цветом. `outlineVariant` недостаточно контрастен для единственного признака интерактивного поля; используй `outline`, явную подпись и focus ring. Статусы дублируются словами и иконкой. Четыре цвета участников помогают следить за схемой, а не кодируют готовность обмена.

При изменении палитры проверяй контраст основных текстовых пар не ниже 4.5:1; важные границы контролов и индикатор фокуса — 3:1. Это базовые проверки, не полная сертификация доступности страницы. Скрипт палитры не видит прозрачные слои, фоновые изображения и фактически отрисованные состояния.

## Типографика

Используй шрифт с кириллицей и явно загруженными нужными начертаниями. Для «Круга» подходит Golos Text или Manrope при наличии лицензированного локального файла; системный стек остаётся рабочим fallback. Не указывай отсутствующий шрифт так, будто он уже установлен. Сборка и демонстрация должны работать без обращения к Google Fonts; применяй локальные файлы или системные шрифты.

Роли и стартовые размеры заданы в ассете. Для интерфейса по умолчанию:

- один заголовок страницы 28–36 px; более крупный display только в коротком первом экране;
- заголовки секций 22–24 px, карточек 18–20 px;
- основной текст и ввод 16 px с комфортной высотой строки;
- метаданные 14 px, второстепенные подписи 12 px;
- кнопки и tabs — обычный русский регистр, без обязательного ALL CAPS;
- числовая метрика не крупнее смыслового итога «Вы получите велосипед».

Длинное пожелание переносится. Отдаваемая и получаемая вещи не обрезаются так, чтобы потерялся смысл. У тегов есть перенос или контролируемое раскрытие. На узком экране увеличивается высота компонента, а не уменьшается весь текст.

## Геометрия и поверхности

Базовый шаг — 4 px, основные интервалы 8/12/16/24/32. Контент ограничен примерно 1200 px; на широком экране добавляется воздух, а не бесконечно растягиваются поля.

Используй согласованные радиусы: 12 для контролов/малых контейнеров, 16–28 для карточек и диалогов, полный радиус для chips и приоритетных кнопок. Элементы формы могут быть прямоугольнее рекламного блока. Форма, кнопка и каждая маленькая плашка не обязаны иметь одинаковый радиус.

Глубина подчёркивает взаимодействие: большая часть карточек тональная или с лёгкой границей; диалог/меню получает умеренную тень. Большая размытая тень под каждой строкой разрушает иерархию. Важный блок можно выделить более насыщенной тональной поверхностью вместо ещё одной рамки.

## Адаптивная композиция

Рабочие пороги проекта: компактный экран до 600 px, средний 600–839 px, широкий от 840 px. Это ориентиры, проверяемые по содержимому; не обещание, что любой экран помещается только из-за breakpoint.

На мобильных экранах используй Framework7 React с явной темой `md`, включая при просмотре на iPhone. На десктопе — Material UI. Начальный порог выбора оболочки — 840 px, вынесенный в конфигурацию; проверь поворот телефона и изменение ширины. Смена представления не должна терять введённые данные, менять выбранного пользователя или выполнять повторную запись.

- Каталог: одна колонка на телефоне, затем две/три по фактической ширине карточки. Фильтры переносятся или открываются компактной панелью.
- Форма: одна смысловая последовательность «Отдаю → Хочу → Условия», на desktop допустима спокойная сводка справа. Ограничения раскрываются дополнительно.
- Навигация: компактная на телефоне, более явная на desktop. Каждый пункт имеет существующий маршрут или рабочую вкладку.
- Крупная кнопка создания на каталоге допустима как extended FAB. На форме приоритет у кнопки сохранения; плавающая кнопка не перекрывает поля и системные safe areas.
- Нижние действия учитывают `env(safe-area-inset-bottom)` и пространство экранной клавиатуры. Цель касания — около 48×48 px; видимая иконка может быть меньше.

## Компоненты продукта

| Компонент | Визуальный контракт |
| --- | --- |
| Заявка | Название вещи, явно разделённые «Отдаёт»/«Хочет», компактная зона, существенное ограничение и понятный переход в детали. |
| Фильтр | Видимая подпись, selected-state, возможность сброса. Не все chips являются кнопками — семантика соответствует действию. |
| Поле формы | Постоянная подпись, пример/подсказка, ошибка рядом с полем. Placeholder не заменяет label. |
| Результат поиска | «Вы получите …», число участников, объяснение совпадения, одно действие «Посмотреть круг». |
| Пустое состояние | Причина и одно полезное действие: добавить заявку, уточнить пожелания или изменить фильтры. |
| Загрузка | Skeleton повторяет будущую геометрию. Сохранение не удаляет весь контекст страницы. |
| Подтверждение | Показывает собственного участника и результат ответа сервера. При ожидании других видны их состояния. |
| Отказ/конфликт | Короткое объяснение, сохранённая история и доступный новый поиск. Ошибка не оформляется как необратимая катастрофа всего сервиса. |

## Обменный круг — ключевой визуальный объект

Ребро показывает передачу вещи от владельца к получателю. Для A «монитор → хочу велосипед», B «велосипед → хочу дрель», C «дрель → хочу монитор» правильный порядок передач: `A → C → B → A`.

Узлы содержат имя и отдаваемую вещь; статус ответа оформлен отдельно. Выдели текущего пользователя и подпиши две строки: «Вы отдаёте …» / «Вы получаете …». Для 2 участников достаточно двух связанных карточек, для 3 — треугольника, для 4 — квадратной или круговой композиции с читаемыми направлениями.

На телефоне основной носитель смысла — последовательный список передач; компактная схема дополняет его. Рёбра, тексты и стрелки не накладываются. У SVG есть доступное описание, а интерактивные узлы доступны клавиатурой.

Анимация может провести внимание по уже существующему ребру или показать ответ участника. Она не должна изображать успешный обмен раньше серверного подтверждения. При reduced motion остаётся понятное мгновенное изменение.
