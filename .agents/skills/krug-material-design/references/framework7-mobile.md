# Мобильный интерфейс на Framework7 React

Framework7 — явный выбор пользователя для мобильной веб-версии «Круга». Используй React-компоненты Framework7 и Material-тему `theme: 'md'`. Десктопное представление остаётся на Material UI; обе оболочки работают с одним доменом, API и сессией.

## Подключение

Проверь совместимые стабильные версии `framework7`, `framework7-react` и текущего React в package/exports и [официальной инструкции](https://framework7.io/react/installation). Ставь зависимости при реализации мобильного интерфейса. Новый проект через Framework7 CLI не нужен: сохраняется существующий Next.js.

Изолируй браузерную инициализацию, зарегистрируй Framework7 React plugin и используй структуру App/View/Page согласно [документации инициализации](https://framework7.io/react/init-app). Проверь публичные API установленной версии: даже официальные примеры могут использовать старый ReactDOM, который нельзя переносить в текущий App Router.

Мобильная оболочка находится на клиентской границе. Если библиотеке нужен DOM при импорте, загружай только этот модуль через `next/dynamic` с `ssr: false` внутри клиентского компонента. Сверь с `node_modules/next/dist/docs/01-app/02-guides/lazy-loading.md`. Серверный layout и остальные страницы не требуют общего отключения SSR.

Первый серверный и клиентский рендер согласованы. Не выбирай несовместимые деревья по `window.innerWidth` или User-Agent прямо во время серверного рендера. Выбор оболочки должен иметь стабильное начальное состояние и fallback, сохраняющий геометрию экрана.

## Владение маршрутизацией

Сначала проверь минимальный сценарий: каталог → заявка → круг → Back → прямая ссылка → reload. Для одного URL один механизм управляет history.

Предпочтительны общие веб-адреса Next.js. Если Framework7 View нужен только как контейнер, проверь поддержанный способ отключить его router и перехват ссылок в установленной версии. Не считай, что `next/link` и Framework7 Link автоматически совместимы.

Если для выбранных компонентов необходим полноценный Framework7 router, явно отдели область его владения и согласуй вход/выход с Next.js. Не поддерживай две несинхронизированные истории одного маршрута. Решение должно сохранять deep links, браузерный Back и идентификатор открытого круга; проверь это интеграционно, а не только по примеру запуска.

## Компоненты и тема

Используй Navbar, Toolbar/Tabbar, List/ListInput, Card, Button, Sheet/Popup, Segmented/Tabs и Preloader/Skeleton из Framework7 по потребностям экрана. Внутри мобильной оболочки не вставляй MUI Dialog или MUI TextField ради отдельных элементов.

Начни с явно выбранной Material-темы, а не `auto`, если нужен одинаковый язык Material на Android и iPhone. Значение темы и её поведение описаны в [Framework7 App API](https://framework7.io/docs/app).

Общие токены «Круга» отображаются на публичные CSS-переменные установленного Framework7; не копируй неподтверждённые названия переменных из другой версии. Сохрани зелёный акцент, светлые поверхности, кириллицу и доступные состояния. Наличие темы `md` не отменяет проверки фактического внешнего вида и контраста.

Стили Framework7 могут менять глобальные элементы и классы `.page`, `.button`, `.navbar`, `.dialog`. Ограничь их влияние, проверь root-классы и очистку состояния при размонтировании. Протестируй MUI и Data Studio после открытия мобильной оболочки и изменения ширины; простой lazy import CSS не гарантирует его выгрузку.

## Общее состояние и жизненный цикл

DTO, запросы, серверные ошибки, пользователь и черновики живут выше различий представления. React hooks/сервисы используются обеими оболочками; API сохранения и правила согласия не дублируются.

Инициализация и очистка Framework7 должны выдерживать повторный mount/unmount и React StrictMode. Не создавай экземпляр на каждом рендере. Императивные вызовы выполняются после готовности экземпляра; события, polling, модальные окна и глобальные эффекты освобождаются корректно.

Изменение ширины, открытие sheet и смена вкладки не должны повторно отправлять заявку или подтверждение. Безопасность жестов и кнопок остаётся в серверном API. Swipe и pull-to-refresh не могут быть единственным способом выполнить обязательное действие.

## Мобильная проверка

Проверь ввод при открытой клавиатуре, safe areas, длинную форму, прокрутку Page, нижние панели, диалоги, смену ориентации и восстановление фокуса. Контент и CTA не перекрываются. У схемы круга есть читаемый текстовый эквивалент.

Браузерный сценарий проходит на мобильной и десктопной оболочках с одинаковыми API и результатами. До завершения проверь прямой URL, Back/reload и отсутствие дублированных событий. Успешная сборка одна не доказывает корректную интеграцию двух UI-систем.
