# Применение ИИ и проверка результата

ИИ использован как помощник разработки: предложил модели, алгоритм, обработку транзакций, компоненты и проверки. В работающем сервисе внешняя LLM не вызывается. Поиск циклов и обязательные ограничения должны быть воспроизводимыми и проверяться обычными тестами.

Человеческий просмотр командой и пользовательские интервью **ещё нужны**. Приведённые проверки выполнены инструментами разработки; они не заменяют проверку людьми и не доказывают спрос.

| Задача | Предложенное решение | Как проверено | Фактический результат / ограничение |
| --- | --- | --- | --- |
| Сопоставление | Справочник русских форм, ё→е, тип/категория, отрицания, обязательные условия | `tests/krug-domain.test.ts`: положительные и отрицательные примеры | Исправлено распространение «не» через запятую на положительное пожелание. Сложные фразы всё ещё требуют проверки на реальных данных |
| Ориентация графа | Ребро отдающий→получатель, bounded DFS до 4 | Фикстура A–L, ожидаемые ACB/AED/FIHG/JK, проверка личного результата | Найдено и исправлено перезаписывание первого поворота найденного цикла при дедупликации |
| Производительность | Подготовка текстов один раз на снимок, переиспользование matcher в DFS | `npm run benchmark:krug` | До оптимизации повторная подготовка текстов съедала бюджет на 250 узлах. После неё 83 цикла найдены за 41,49 мс на разреженном наборе; это не проверка плотного городского графа |
| Надёжность | Транзакция последнего согласия и условное резервирование | `tests/krug.integration.test.ts`: два финальных подтверждения конкурирующих кругов, одновременные ответы, отмена/expiry | Один из конфликтующих кругов согласуется, второй получает 409; двойного резерва нет |
| Авторизация | HttpOnly cookie, hash токена, owner/member checks | Реальная MongoDB и разные браузерные контексты | Чужие изменения и ответы запрещены; локальная сессия не подтверждает личность человека |
| Сохранность | Помеченный seed/reset, обычные записи отдельно | Новый MongoClient читает сохранённую запись; reset оставляет обычную заявку и произвольную коллекцию | Демоданные сбрасываются воспроизводимо без `dropDatabase` рабочей базы |
| Интерфейс | Общие токены, MUI desktop и Framework7 md mobile, SVG-схема с текстом | `tests/krug.spec.ts`, скриншоты `.local/qa/` | Через форму создана заявка, три отдельные сессии согласовали круг на обеих оболочках; проверены отказ, альтернатива, пара, четверка и пустой результат |
| Интеграция Next/F7 | Browser-only модуль и один владелец history | Console errors, deep link/reload/Back, изменение ширины | Исправлена ошибка instant validation новой версии Next: локальный Suspense и сохранение page-slot |
| Изоляция UI | Префиксы CSS и ограниченные эффекты F7 | Исходный тест Data Studio и переход после mobile | Исправлены global button width и ripple/activeState, затрагивавшие студию. Нет одновременных полноценных оболочек |

## Воспроизведение

```bash
npm run test:domain
npm run test:krug
npm run test:db
npm run test:ui
npm run benchmark:krug
node .agents/skills/krug-material-design/scripts/check-contrast.mjs
npm run typecheck
npm run lint
npm run build
```

Домен: 8 проверок; интеграция Круга: 10; старый API студии: 9. Браузерные сценарии находятся в двух spec-файлах: четыре для Круга и сохранённый сквозной сценарий студии. Итоговое состояние проверок фиксируется в `implementation-plan.md`.

Проверка токенов: 14/14 непрозрачных пар прошли пороги контраста. Это не автоматический аудит всех отрисованных пикселей. Браузерные проверки проведены в Chrome на ширинах 320, 390, 768 и 1440 px; физические Android/iOS устройства и реальная экранная клавиатура требуют отдельного просмотра командой.

Артефакты: `.local/qa/desktop-circle.png`, `mobile-circle.png`, `studio-desktop.png`, `studio-mobile.png`, `benchmark.json`. Папка локальная и не коммитится. При падении браузерной проверки Playwright сохраняет screenshot и trace в `test-results/`.

## Что команда должна проверить сама

Понятность подписей «отдаёте/получаете», читаемость схемы и длинных названий, работа с клавиатурой на собственном телефоне, подходящие зоны Владивостока, корректность словаря типов на новых заявках. Не заявляем «проверено человеком», экономию времени относительно ручной разработки, проведённый пилот или реальные экологические показатели.
