# Архитектура Круга

Next.js 16.4.6 / React 19.3 обслуживает общие URL. Express 5 проверяет сессии и входные данные, вызывает доменные сервисы. MongoDB 6 driver работает с локальным replica set `krug-rs`. Runtime-поиск полностью детерминирован, без внешних AI API.

## Модули

| Слой | Ответственность |
| --- | --- |
| `shared/krug/reference.ts`, `schemas.ts`, `types.ts` | Справочники, строгий ввод и контракты |
| `server/domain/krug/matching.ts` | Нормализация, типы, ограничения, объяснения |
| `server/domain/krug/graph.ts` | Списки смежности, DFS до 4, каноническая подпись |
| `server/repositories/krug.ts` | Коллекции, индексы, DTO |
| `server/services/krug.ts` | Сценарии, версии, транзакции, демонабор, метрики |
| `server/services/session.ts` | Случайные токены, SHA-256, HttpOnly cookie |
| `src/components/krug/state.tsx` | Одна сессия и черновики выше оболочек |
| `application.tsx`, `mobile-host.tsx`, `ui.tsx` | Next-навигация, MUI и Framework7 адаптеры |

## Данные

`krug_users`: имя, район, признак демо. `krug_sessions`: hash токена, userId, expiresAt (TTL). `krug_listings`: поля предложения/пожелания, ownerId, version, статус active/reserved/archived. `krug_circles`: упорядоченные заявки и версии, снимки участников, решения, status/revision/expiry/signature. `krug_events`: события переходов, поисков и уникальных просмотров вариантов.

Связи в MongoDB — ObjectId, время — Date. API сериализует ID в строки и даты в ISO; внутренние datasetId и participantIds не включаются в DTO. Seed использует уникальные составные ключи datasetId/demoKey и `$setOnInsert`. Подпись круга уникальна, включает версии.

## Сопоставление и граф

Ребро **A → B означает «A передаёт свою вещь B»**. Проверяются пожелания B: исключения/отрицания, тип или категория, минимальное состояние, обязательные/запрещённые слова. Затем рассчитывается технический балл и объяснения. Балл не является вероятностью успеха обмена.

Нормализация: нижний регистр, ё→е, пунктуация, словарь форм известных типов. Отрицания ограничены предложением/частью фразы; это консервативная эвристика, не полный анализ русского языка. Для неизвестного типа нужен достаточный точный словесный overlap. Настройки ввода не могут назначить чужого владельца.

Перед обходом тексты подготавливаются один раз на снимок поиска. Строится ориентированный граф O(N²), затем ограниченный DFS. Путь замыкается только ребром последнего к первому. Длина 2–4, владельцы и заявки уникальны. Для всего круга проверяется пересечение зон, интервалов минимум 15 минут и индивидуальные лимиты длины. Прошедшие окна не используются. Без указанных окон/зон соответствующее ограничение свободно.

Каноническая подпись — минимальный лексикографический циклический поворот пар `[listingId, version]`. Направление не переворачивается. Ранжирование: длина, худшее совпадение, средний балл, подпись. Отклонённая версия исключается из повторного поиска и из расчёта общих метрик. Изменение вещи создаёт другую подпись.

Поиск по своей заявке ограничен 250 узлами, 100 000 раскрытий, 750 мс и 30 выдаваемыми кандидатами. Общие метрики используют 1 000 мс и до 10 000 возвращаемых кандидатов. `truncated` означает неполный обход; `total` — число найденных, а не гарантированный размер всего пространства. Бюджет времени проверяется между шагами DFS, поэтому это мягкий лимит, не SLA.

## Согласование

`proposed → agreed`, когда согласны все; `proposed → declined/cancelled/expired/invalidated`. Из `agreed` возможны `cancelled/expired`. Истечение по умолчанию через 24 часа. Последнее согласие обновляет резерв всех вещей, статус круга, конкурирующие предложения и журнал **в одной MongoDB-транзакции** со snapshot/majority.

Каждая вещь условно обновляется только при active и ожидаемой версии. Конкурирующие транзакции получают write conflict; драйвер повторяет допустимые транзакции. Разделяемое поле круга и revision предотвращают потерю одновременных ответов. Повтор принятого ответа безопасен. До последнего согласия вещи не резервируются.

Редактирование/архивирование инвалидирует старые proposed-круги. Зарезервированную вещь нельзя изменять: сначала отмена. Отмена/истечение освобождает только вещи с `reservedBy` этого круга. Проверка истечения вызывается до поиска/действий и чтения связанных ресурсов; отдельного worker пока нет. `agreed` не означает физический обмен.

## Оболочки и навигация

Порог 840 px задан в токенах. Desktop использует MUI/Emotion App Router Cache Provider; mobile — Framework7 React `theme="md"`. F7 App инициализируется при первом открытии мобильного интерфейса и затем сохраняется между маршрутами и изменениями ширины; View/Page существуют только при активном мобильном режиме. F7 View имеет `router={false}`: history, deep links и Back принадлежат Next.js. Нет двух одновременно активных экранов/обработчиков. Черновик живёт в общем контексте и переживает смену ширины, но не перезагрузку до сохранения.

F7 загружается браузером внутри локального Suspense. Первый рендер согласован через `useSyncExternalStore` с серверным snapshot. Отдельно сохраняется Next page-slot для новой проверки instant navigation. CSS F7 и Data Studio сгенерированы с префиксами; переход mobile→desktop→studio не оставляет глобального reset. Токены копируются в обычный исходный файл, skill не нужен приложению во время работы.

## Безопасность и эксплуатация

API и MongoDB слушают loopback. Запись требует JSON, собственного клиентского заголовка и допустимого Origin/Host. Cookie HttpOnly/SameSite=Lax, хранится только hash случайного 256-битного токена, срок проверяется независимо от TTL. Проверяются владелец заявки и членство круга; чужой ответ запрещён. Ввод ограничен строгими Zod-схемами, ID проверяются, поисковый regex экранируется. Ограничение тела 1 МБ, rate limit для локального API. Секреты и сырые Mongo-ошибки в ответ не попадают.

Data Studio сохраняет свой API, но `krug_*` скрыты и запрещены на чтение/запись. Прямой доступ разработчика к MongoDB остаётся административным. Это локальная граница безопасности, не готовая интернет-платформа. Single-node replica set не даёт резервного узла; резервные копии нужны отдельно.
