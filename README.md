# Vibe Farpost — Data Studio

Локальный клиент для наполнения MongoDB на Next.js, React и TypeScript.
Небольшой Express-сервер в `server/` обрабатывает базу, проверяет данные и хранит настройки форм.
Заранее заданных предметных сущностей нет: коллекции и их поля создаются по мере работы.

## Запуск на компьютере

Нужны Node.js 20.9+ и установленный `mongod` (MongoDB Community Server).
На текущем компьютере MongoDB уже установлена. Все npm-зависимости проекта установлены.

```bash
npm run dev
```

Команда запускает три процесса:

| Процесс            | Адрес / расположение         |
| ------------------ | ---------------------------- |
| Next.js, интерфейс | http://127.0.0.1:3000        |
| Express, API       | http://127.0.0.1:4000/api/db |
| MongoDB            | mongodb://127.0.0.1:27018    |
| База               | `vibe_farpost`               |
| Файлы базы         | `.local/mongodb/`            |
| Журнал MongoDB     | `.local/mongodb.log`         |

MongoDB и API слушают локальный интерфейс `127.0.0.1`.
Next.js перенаправляет `/api/db/*` на Express, браузер не подключается к MongoDB напрямую.
После остановки и перезапуска данные сохраняются. `.local/` исключена из Git.
Остановка общей команды — `Ctrl+C`; все три процесса получают сигнал завершения.

При первом запуске из нового checkout:

```bash
npm install
cp .env.example .env
npm run dev
```

Параметры подключения находятся в `.env`, образец — `.env.example`.
При смене локального порта MongoDB измените и `MONGODB_LOCAL_PORT`, и порт в `MONGODB_URI`.
Для другого расположения бинарника задайте `MONGOD_BINARY`.
Для уже запущенной или внешней MongoDB укажите её URI и запускайте отдельно `npm run server:dev` и `npm run web:dev`.

## Работа с данными

1. Создайте коллекцию: укажите подпись и системное имя на латинице.
2. Задайте поля: ключ, подпись, тип и обязательность.
3. Добавляйте и редактируйте записи через автоматически построенную форму.

Доступны текст, длинный текст, число, логическое значение, дата и ссылка.
Сервер проверяет типы, обязательные поля, даты и адреса до записи в MongoDB.
Документы хранят пользовательские поля непосредственно в корне; `_id` — ObjectId,
`createdAt` и `updatedAt` — даты MongoDB, добавляемые сервером.
Таблица поддерживает страницы по 15 записей и удаление отдельной записи с подтверждением.

В «Поля формы» можно менять структуру. Пока коллекция пустая, поля редактируются свободно.
Если записи уже есть, можно менять подписи и добавлять необязательные поля.
Смена типов, обязательности и удаление существующих полей требуют отдельной миграции данных;
сервер отклоняет такие изменения, чтобы структура не расходилась с сохранёнными записями.

База создаётся автоматически при запуске API. Системная коллекция `_collections` содержит
описания пользовательских коллекций и форм. Для каждой новой коллекции создаётся индекс
по дате добавления и идентификатору. Рабочие коллекции изначально пусты.

## Структура

```text
server/
  index.ts              # запуск Express и подключение MongoDB
  app.ts                # локальный API, ограничения запросов, обработка ошибок
  config.ts             # переменные окружения
  db/
    client.ts           # подключение и пул MongoDB
    collections.ts      # системная коллекция и инициализация индексов
  routes/
    collections.ts      # создание, список и настройка коллекций
    documents.ts        # чтение, запись, изменение и удаление документов
  lib/
    validation.ts       # схемы и проверка значений форм
    errors.ts           # ошибки API
  scripts/init.ts       # повторная инициализация базы
shared/database.ts      # общие типы клиента и сервера
scripts/mongodb.mjs     # запуск локального mongod с файлами внутри проекта
src/components/database/# интерфейс клиента и формы
src/lib/database-api.ts # запросы браузера к API
tests/                  # интеграционные и браузерные проверки
```

## API

| Метод  | Маршрут                                                  | Действие                             |
| ------ | -------------------------------------------------------- | ------------------------------------ |
| GET    | `/api/db/health`                                         | Подключение и общая статистика       |
| GET    | `/api/db/collections`                                    | Коллекции, поля и количество записей |
| POST   | `/api/db/collections`                                    | Создать коллекцию и описание формы   |
| PUT    | `/api/db/collections/:name`                              | Обновить описание формы              |
| GET    | `/api/db/collections/:name/documents?page=1&pageSize=15` | Страница записей                     |
| POST   | `/api/db/collections/:name/documents`                    | Добавить запись                      |
| PUT    | `/api/db/collections/:name/documents/:id`                | Изменить запись                      |
| DELETE | `/api/db/collections/:name/documents/:id`                | Удалить запись                       |

Для изменений необходим заголовок `X-DB-Client: vibe-farpost`; для POST/PUT — также
`Content-Type: application/json`. Тело записи: `{ "values": { "key": "value" } }`.
Внешние Origin и обращения с внешним Host отклоняются, CORS-доступ не включён.
Это локальный инструмент администратора; для публичного размещения потребуется авторизация.

## Команды и проверки

```bash
npm run db:dev       # только MongoDB
npm run db:init      # проверить подключение и создать системные индексы; MongoDB должна работать
npm run server:dev   # только API, с перезапуском при изменениях
npm run web:dev      # только Next.js
npm run typecheck   # типы клиента и отдельного сервера
npm run lint
npm run test:db     # реальная MongoDB должна работать
npm run test:ui     # приложение, API и MongoDB должны работать
npm run build
```

Интеграционные проверки создают отдельную временную базу и удаляют её после выполнения.
Браузерная проверка создаёт временную коллекцию `ui_check_*`, заполняет форму, редактирует
запись, добавляет поле и проверяет мобильный экран; временная коллекция удаляется после теста.
По умолчанию используется установленный Google Chrome. Другой браузер можно выбрать
через `PLAYWRIGHT_CHANNEL`, другой адрес приложения — через `APP_URL`.
Снимки интерфейса сохраняются в `.local/qa/`.

Для запуска собранного приложения: сначала `npm run db:dev`, затем в другом терминале
`npm run build` и `npm start`. API и Next.js запускаются вместе.
